==============================================================================
PART 2 - GENERATED FILES
==============================================================================

Twelve files written by generate-luts.py in this folder. Jeremy Ellis and
contributors place these files, and the script that writes them, in the
PUBLIC DOMAIN (CC0 1.0 Universal). No rights are reserved and no attribution
is required.

The generator uses the Python 3 standard library only, and its output is
DETERMINISTIC: every number is written with '%.6f' formatting, which is
locale-independent, so the bytes are the same on every machine. This was
checked by running it twice, and again under a German locale, and comparing
SHA-256 sums.

Rows are ordered as the format requires: red changes fastest, then green,
then blue. The grid point at index i on an axis of size N is i/(N-1). At six
decimals that is EXACT for the 17, 33 and 65 grids (1/16, 1/32 and 1/64 all
terminate in binary and in six decimal places), so identity tables hold exact
values, not rounded ones. The 1024 point 1D grid is 1/1023 and does round.

The 'definition' line of each entry below is the contract: it is repeated in
the file's own comment header and in the DEFINITIONS dictionary in
generate-luts.py, and a test may assert computed values against it.

==============================================================================
PART 3 - INTENTIONALLY INVALID FILES (invalid/)
==============================================================================

EVERY FILE IN invalid/ IS MALFORMED ON PURPOSE AND MUST NEVER BE FIXED. They
are negative fixtures: the reader is supposed to REFUSE them, and to refuse
them with a message naming what is wrong and where. Correcting one of these
files does not improve the corpus - it silently inverts the test that depends
on it, which would then be asserting that a VALID file is refused.
invalid/DO-NOT-FIX.txt says the same thing beside the files themselves.

Neither file was damaged by anyone here. Both are real files taken intact
from open-source projects already vetted for Part 1, under the same licences,
and both were verified against their upstream git blob SHA-1 exactly as the
valid downloads were. One is defective by ACCIDENT (its author's generator
produced a NaN), the other by DESIGN (its author ships it as their own
should-not-parse fixture). Having one of each is the point: a reader must
survive both the deliberate garbage and the plausible-looking file with one
bad row in the middle.

A test that walks the corpus must EXCLUDE invalid/, or assert failure for it.
