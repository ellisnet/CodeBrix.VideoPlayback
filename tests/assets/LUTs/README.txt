================================================================================
README: tests/assets/LUTs
Colour lookup tables - the sample corpus, and where every byte of it came from
================================================================================

This folder holds .cube colour lookup tables for the LUT effect (the reader is
src/CodeBrix.VideoPlayback/Color/Luts/CubeLutFile.cs and the effect is
src/CodeBrix.VideoPlayback/Effects/LutEffect.cs, both in the core library). They
are DATA. Nothing here is compiled into any assembly, nothing here is a
dependency of anything, and none of the three shipped packages contains a single
one of these files. They exist so that tests have real files to parse and samples
have real looks to draw.

There are three kinds of file, in three folders:

    found/      nine files downloaded from six independent open-source projects,
                every one of them CC0, a public-domain dedication, or MIT, with
                the licence read at its source and the file's own origin traced.

    generated/  twelve files written by generate-luts.py in this folder, and
                placed in the PUBLIC DOMAIN. See the declaration below.

    invalid/    two files that are MALFORMED ON PURPOSE, for negative tests.
                THEY MUST NEVER BE FIXED. See the section below, and the
                DO-NOT-FIX.txt sitting beside them.

MANIFEST.txt records, for every one of the twenty-three files: where it came
from or how it is defined, its size, its table type and size, its SHA-256, and
what the validator said about it. LICENSES/ holds the verbatim licence text of
each of the six upstream projects, and covers the invalid pair too - both come
from projects already listed there.


ONLY .cube
==========
This program reads ONE lookup-table format: the IRIDAS/Adobe ".cube" text file.
It does not read .3dl, .look, .csp, .spi3d, .spi1d, .clf, .ctf, .vf, .cub, .hdl,
or Hald CLUT images (a Hald CLUT is a PNG, not a table file). Files in those
formats were passed over during the hunt no matter how they were licensed, and
none should be added here. If support for another format is ever wanted, that is
a decision about the reader, and this folder follows it rather than leading it.

Within .cube, both table kinds are here: LUT_3D_SIZE tables at sizes 2, 3, 4, 17,
33 and 65, LUT_1D_SIZE tables at sizes 4 and 1024, and one file that carries a 1D
shaper AND a 3D table together, which is the arrangement Resolve's dialect
allows.


THE LICENCE BAR, AND HOW IT WAS APPLIED
=======================================
Three licences were acceptable, and nothing else:

    * CC0 1.0 Universal
    * an explicit public-domain dedication (the Unlicense counts)
    * MIT

Every acceptance required BOTH of the following, checked by hand:

 1. THE LICENCE, AT ITS SOURCE. A LICENSE file in the same repository as the
    file, or an explicit dedication on the page hosting it. Not a badge, not a
    third party's summary, not a package manifest's "license" field on its own.
    The text of all six is captured under LICENSES/.

 2. THE FILE'S OWN ORIGIN. A permissive licence on a repository says what its
    author may grant, not what its author had the right to grant. So for every
    candidate the question asked was: did the author of THIS repository make
    THIS table? Where a file was stated or shown to come from somewhere else -
    a grading application's bundled set, a camera manufacturer, a game, a free
    download site, another collection - the origin was chased, and where the
    origin's own licence was not clearly one of the three above, the file was
    REJECTED. That is why the accepted set is small.

"Free to download", "royalty free", "free for commercial use", "100% free" and
"free for personal and commercial projects" are NOT licences and were treated as
rejections everywhere they were met. So were CC-BY, CC-BY-SA, CC-BY-NC, Apache
2.0, BSD-3-Clause and GPL, which are perfectly good licences that this bar simply
does not admit.


WHAT WAS ACCEPTED
=================
Six projects, nine files. Full detail, hashes and per-file notes in MANIFEST.txt.

    aras-p/smol-cube             MIT OR Unlicense   1 file
      Its own synthetic test fixture, from tests/luts/synthetic/. The other LUTs
      in that repository were rejected - see below.

    diegoinacio/cube-lut-factory.js   MIT           2 files
      The library's own test fixtures; each carries an in-file copyright header
      naming the author and pointing back at that repository.

    NiKoTron/dart-lut            MIT                3 files
      The library's own hand-written fixtures; one states the arithmetic it
      encodes in its first comment line.

    cgardev/cameraluts           MIT                1 file
      Procedurally generated by Go programs committed in the same repository,
      from published transfer functions. Computed mathematics, not a
      redistributed vendor file.

    darkyboys/opensource-luts    CC0-1.0            1 file
    darkyboys/gtgluts            CC0-1.0            1 file
      Two packs by one author, each with the full CC0 legal code as its LICENSE
      and each .cube sitting beside the .json project file of the author's own
      generator, which corroborates the authorship claim.


WHAT WAS REJECTED, AND WHY
==========================
The rejects are the more useful half of this record, because they are what stops
the next person re-treading the same ground.

REJECTED ON ORIGIN (the repository's licence was fine; the files were not the
repository author's to license):

  aras-p/smol-cube, the other six LUTs in tests/luts/
      resolve-DCI-P3 Kodak 2383 D65.cube and resolve-LMT ACES v0.1.1.cube are
      DaVinci Resolve's bundled tables (Blackmagic Design); the four
      tinyglade-*.cube files carry a commercial game's name; khronos-
      pbrNeutral.cube comes from KhronosGroup/ToneMapping, which is Apache-2.0

      for this corpus).

  mrdoob/three.js (MIT), examples/luts/
      The example page itself credits "LUTs from RocketStock, FreePresets.com".
      Both are free-download sites without an open licence. Rejected.

  ronan18/SwiftCube (MIT), Tests/SwiftCubeTests/SampleLUT.cube
      The file's own header reads "RED Digital Cinema Output Transform LUT for
      IPP2 / Creatives by Eric Weidt / BMD cube from Truelight v4.0". A camera
      manufacturer's transform. Rejected.

  mv-lab/nilut (MIT), dataset/cube-files/LUT01.cube
      TITLE "Generated by Resolve", and the project README describes its dataset
      as images "processed using professional 3D LUTs on Adobe Lightroom". The
      table's own origin is not stated. Rejected.

  moebiussurfing/ofxGpuLutCube (MIT), 303 bundled .cube files
      Named "A1 (sunset warm)", "A10 (teal orange)" and so on, with no statement
      anywhere of who made them or under what terms. Rejected.

  scernst13/HaldCLUT-Cube-Files (CC0-1.0), 14 Kodak film-emulation tables
      This one is worth the paragraph. The repository does carry the full CC0
      legal code, but its README says the files are conversions of HaldCLUTs the

      RawTherapee film-simulation collection (Pat David, Pavlov Dmitry, Michael

      collection, and Pat David's own site is CC-BY-SA 4.0, not CC0. An uploader

  jonmatifa/a6000-LUTs (CC0-1.0), 3 tables
      The two log tables were generated by the author in DaVinci Resolve from

  IRCGraphic/SATURATION-TECHNIQUE-LUTS (CC0-1.0), 3 tables
      Synthesised by the uploader, but explicitly to reproduce a technique from

invalid/ - FILES THAT ARE BROKEN ON PURPOSE. DO NOT FIX THEM.
============================================================
Two files, and everything in this folder is MALFORMED ON PURPOSE:

    invalid/GTG Channel Cooler.cube    CC0-1.0, darkyboys/opensource-luts
        267,185 bytes. A perfectly ordinary LUT_3D_SIZE 17 table with the right
        4,913 rows - except that line 274 is literally "NaN NaN NaN". Broken by
        ACCIDENT: its author's generator emitted that row, and the file was
        downloaded with the defect intact.

    invalid/bad_cube.cube              MIT, NiKoTron/dart-lut
        161 bytes. Broken by DESIGN: its author ships it as their own
        should-not-parse fixture, and says so in its first comment. Line 10 is
        "1.0 0.sd75 0.0" and line 12 is "0.x0 0.25 1.0" - three tokens each, but
        the tokens are not all numbers - so the file promises 8 rows and delivers
        6 readable ones.

Having one of each is the point. A reader has to survive the obvious garbage AND
the plausible-looking file with a single bad row buried in the middle of four
thousand good ones.

THE RULES FOR THIS FOLDER:

    DO NOT "correct" these files, DO NOT delete the bad rows, and DO NOT run a
    formatter, a linter or a cleanup script over them. Fixing one does not
    improve the corpus: it silently INVERTS the test that depends on it, which
    would then be asserting that a valid file is refused.

    A test that walks the corpus must EXCLUDE invalid/, or assert failure for
    it. Any code that globs tests/assets/LUTs/**/*.cube and expects every match
    to load will break here, correctly.

    These files are expected to FAIL. In the validation results, failing IS the
    pass: the validator reports them as "OK-REFUSED", and would report a problem
    if either one ever parsed successfully.

Both are licence-clean and both come from projects already vetted for found/,
under the same licences, so LICENSES/opensource-luts.txt and LICENSES/dart-lut.txt
cover them. Both were verified against their upstream git blob SHA-1 exactly as
the valid downloads were. MANIFEST.txt Part 3 records their hashes, their
provenance, what is wrong with each, and the exact errors each one must produce.
DO-NOT-FIX.txt repeats the warning inside the folder itself, where someone tidying
up will actually see it.


THE PUBLIC-DOMAIN DECLARATION FOR generated/
============================================
The twelve files in generated/, AND the generate-luts.py script that writes them,
were created for this repository. Jeremy Ellis and contributors place all of
them in the PUBLIC DOMAIN, under the Creative Commons CC0 1.0 Universal public
domain dedication. No rights are reserved. No attribution is required. Anyone
may copy, modify, publish, use, sell or distribute them, for any purpose,
commercial or non-commercial, by any means.

They are not derived from any third-party table. Each is defined by arithmetic
stated in the file's own comment header, in the DEFINITIONS dictionary in
generate-luts.py, and in MANIFEST.txt - a matrix, a curve, a per-channel scale -
and computed from that arithmetic alone.

    python3 generate-luts.py [output-folder]

The script needs the Python 3 standard library and nothing else: no package is
imported, downloaded or installed. Its output is deterministic - every number is
written with "%.6f" formatting, which is locale-independent - so running it again
rewrites byte-identical files. That was checked by running it twice and then a
third time under a German locale, and comparing SHA-256 sums.

Six decimals is not an arbitrary choice: on the 17, 33 and 65 grids the step is
1/16, 1/32 and 1/64, all of which terminate within six decimal places, so the
identity tables hold EXACT values rather than rounded ones, and invert_33.cube is
an exact mathematical inversion. A test may assert equality against those, not
just closeness.


HOW THE FILES WERE VALIDATED
============================
Every one of the twenty-three files was parsed and checked before it was left
here - the twenty-one valid ones to prove they PARSE, the two in invalid/ to
prove they are REFUSED. Per file:

    * a size keyword is present - LUT_3D_SIZE or LUT_1D_SIZE - and neither is
      stated twice. A file carrying one of each is recorded as "combined": that
      is Resolve's 1D-shaper-plus-3D-table arrangement, not an error.
    * the data-line count is EXACTLY size^3, or size, or their sum for a
      combined file.
    * every data line holds exactly three numbers.
    * no NaN and no infinity anywhere. This one earned its keep immediately -
      see invalid/ below.
    * every value lies inside the declared [DOMAIN_MIN, DOMAIN_MAX]. Out-of-range
      values are a WARNING and not a failure, because real tables do exceed their
      domain; smol-cube's shaper_3d.cube reaches 13.5.

Result: of the 21 valid files, 21 parse and 0 fail; of the 2 files in invalid/,
2 are correctly refused and 0 wrongly parse. No problems. One warning, on
shaper_3d.cube, for exactly the reason just given. Per-file results, and the
exact errors each invalid file must produce, are in MANIFEST.txt.

Two things worth knowing about this repository's own reader while reading the
corpus - both of them changed on 2026-08-29, when the LUT engine moved into
CodeBrix.VideoPlayback (the core) and gained a writer and a composer:

    * CubeLutFile.Parse HONOURS a domain other than 0..1. It normalises the
      input through [DOMAIN_MIN, DOMAIN_MAX] before the lookup, so a table
      declaring a wider range that is handed an ordinary 0-to-1 picture uses the
      part of itself the picture reaches. generated/domain_test_33.cube declares
      -0.5..1.5 and is therefore a POSITIVE fixture: a test parses it and checks
      the mapping. (A domain that does NOT rise - a maximum at or below its
      minimum - is still refused, by name.)
    * CubeLutFile.Parse also ACCEPTS a file that states BOTH LUT_3D_SIZE and
      LUT_1D_SIZE. found/smol-cube/shaper_3d.cube is such a file, legal in
      Resolve's dialect: the curves are read as a SHAPER that runs first and
      hands its answer to the table, the two INPUT_RANGE keywords give each half
      its own domain, and the pair becomes ONE layer of a composed chain. It too
      is a POSITIVE fixture.

Both files parse cleanly by the format's own rules, and this reader now applies
them as those rules mean.


SIZE
====
The whole folder is about 17.3 MB, and 7.1 MB of that is
generated/identity_65.cube alone - 274,625 rows of text. Each 33-cubed table
costs about 0.95 MB. All nine found files together come to 1.47 MB, six of them
under two kilobytes, and the two in invalid/ add 0.26 MB. If the folder ever
needs to be lighter, MANIFEST.txt closes with the levers, cheapest first.
