THIRD-PARTY SOFTWARE NOTICES AND INFORMATION

CodeBrix.VideoPlayback is a video playback library for .NET: it reads WebM,
Matroska and .cbv containers carrying AV1 video with Opus or Vorbis audio,
exposes a codec-neutral decoder seam, pools decoded frames, presents them to
whatever draws, and converts them to BGRA on the CPU when no graphics device is
doing it. This repository produces TWO MORE ASSEMBLIES beside it:
CodeBrix.VideoPlayback.Skia, which draws those frames through SkiaSharp, and
CodeBrix.VideoPlayback.Authoring, a developer-machine library that WRITES the
files the first one reads. This file ships inside all three packages.

NONE OF THE THREE ASSEMBLIES THIS REPOSITORY PRODUCES INCORPORATES ANY
THIRD-PARTY SOURCE CODE. Nothing is vendored, ported or adapted. Every line of
all three was written for this repository from the published specifications
listed below, and no other implementation of any of these formats was read while
writing them.

The specifications used, all of them public documents:

  RFC 8794     Extensible Binary Meta Language (EBML)
  RFC 9559     Matroska Media Container Format Specifications
  RFC 3533     The Ogg Encapsulation Format Version 0
  RFC 7845     Ogg Encapsulation for the Opus Audio Codec
               (the identification header, the pre-skip field and the granule
               position's meaning)
  ISO/IEC 23091-2  Coding-independent code points - video
               (the colour primaries, transfer characteristics and matrix
               coefficient values, which are the numbers on the wire)
  ITU-T H.273  Coding-independent code points, the ITU text of the same
               material - the definitions of chroma sample siting the CPU
               converter and the shader both implement
  AV1 Bitstream & Decoding Process Specification, Alliance for Open Media
               (the open bitstream unit framing and the sequence header only -
               nothing about decoding)
  AV1 Codec ISO Media File Format Binding, Alliance for Open Media
               (the AV1CodecConfigurationRecord, "av1C")
  WebM Container Guidelines, the WebM Project
  AV1 in Matroska / WebM, Opus in Matroska and Vorbis in Matroska - the codec
               mapping documents for the three codecs this library carries
  Vorbis I specification, Xiph.Org Foundation
               (the identification header's fields and the Xiph lacing of the
               three setup headers)
  IVF: the simple frame container written by the libvpx and AV1 encoding tools,
               as documented publicly alongside them

The uncompressed video format this library defines for its own test and
diagnostics use is described in CBV-FORMAT.txt and in the XML documentation of
CodeBrix.VideoPlayback.Codecs.RawVideoFormat. The bespoke ".cbv" container is
likewise this project's own design, documented in full in CBV-FORMAT.txt.

CodeBrix.VideoPlayback.Skia contains no ported or adapted shader, atlas layout or
colour-conversion code either: its SkSL shader, its lookup-table atlas and its
render paths were written for this repository from ITU-T H.273 and ISO/IEC
23091-2, from SkiaSharp's public API documentation, and from the same
specifications the core converter was written from.

The media files committed directly under tests/assets - the golden corpus - were
generated on the development machine from FFmpeg's own synthetic sources
(testsrc2, sine, anoisesrc) and remuxed with mkvtoolnix. They contain no
third-party recorded material of any kind, and tests/assets/ASSETS.txt records
exactly how each one was made.

tests/assets/authoring is the other corpus, and the one place in this repository
that holds REAL recordings: two 4K clips filmed by Jeremy Ellis on his own phone
and placed by him in the PUBLIC DOMAIN on 2026-08-29, together with the
twenty-four files derived from them, which are Public Domain on the same footing.
Nothing there came from a third party either.
tests/assets/authoring/README.txt carries that declaration and
tests/assets/authoring/MANIFEST.txt the per-file record.

FFMPEG. No FFmpeg binary and no FFmpeg source is shipped by, bundled with or
vendored into any of the three packages this repository produces, and FFmpeg is
not a dependency of the playback library, of the presenter, or of any application
that plays a file. What FFmpeg is, is the tool the AUTHORING package DRIVES: that
library builds command lines and CodeBrix.VideoProcessing launches the ffmpeg and
ffprobe installed on the authoring workstation as child processes. Its own tests
drive that same workstation ffmpeg and skip themselves when it is not installed,
and the sample-video corpus above was produced that way. FFmpeg's licences are
therefore a matter between FFmpeg and whoever installed it on that machine -
which is exactly why the authoring package belongs in a build tool or an asset
pipeline and never in a shipped application. mkvtoolnix is a maintainer's
convenience only: the files it remuxed are committed, and so are the scripts that
regenerate them.
